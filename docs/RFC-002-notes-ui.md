# RFC-002: Notes 界面信息架构与交互设计

**状态**：已确认，已实施（v0.3）
**日期**：2026-09-08
**前置**：RFC-001（Capture → Serialize → Store 主干）
**定位**：定义 Notes 页的设计语言基线——后续 Tags / Collections / Ask My Notes / 深色模式等所有扩展，都必须消费本文定义的结构与 token，不另起炉灶

---

## 1. 设计锚点

本页面是「属于用户自己的 AI Highlight Library」，不是传统 Notes App。三条不可违反的设计语言：

1. **内容是绝对主角**——界面 chrome（导航、按钮、边框）永远退后，正文用最大视觉权重
2. **组织不增加用户负担**——所有组织结构从已存数据（source / conversation / 时间）自动派生；不要求用户打标签、建文件夹（原设计文档 §3 硬约束）
3. **每一屏服务于"重读"**——第一场景是重新发现与重新理解，不是管理

## 2. Note 信息层级（卡片解剖学）

```text
L1 正文（contentMarkdown 渲染）    16px / 行高 1.7，唯一主角
L2 上下文（来源 · 对话标题 · 时间）  13px muted，回答"它从哪来"
L3 操作（Copy / Open / Raw / Delete） hover 才出现，零常驻噪音
L4 状态（源码/渲染、展开/收起）       卡片级 view state
```

细则：

- **长笔记折叠**：渲染高度超过约 280px 时收起 + 「展开全文」；展开状态与现有 rawViewIds 共用同一卡片级 view state 机制
- **时间相对化**：meta 行显示「昨天 / 3 天前」，绝对时间放 tooltip——重读场景里"多久前"比"几月几号"更有认知意义
- meta 行保持后置（内容优先）

## 3. 组织模型：分组，而不是分类

**主分组 = 对话（source + conversationTitle）**。同一对话收藏的多条笔记属于同一次思考，自动聚合：

```text
学习｜求知 - Python 六层架构学习      ChatGPT · 3 条 · Sep 7
┌──────────────────────────────┐
│ Note（组内按收藏时间正序）      │
├──────────────────────────────┤
│ Note                         │
└──────────────────────────────┘
```

- 组排序：按组内最新笔记时间倒序
- 组内排序：按收藏时间**正序**（还原讨论的思考顺序，服务"上下文可回溯"）
- 组头交互：整组折叠/展开、Open Source 跳回对话
- 单条对话的组退化为普通卡片（不显示多余组头 chrome）

**扩展预留**：Tags 进卡片 meta 行；Collections 进 sidebar 手动区域；两者都不推翻对话分组这个默认视图。

## 4. 页面骨架：三区域

```text
┌──────────────────────────────────────────────────┐
│ Topbar: 品牌        [Search…]          [Settings] │ 吸顶
├─────────┬─────────────────────────────────────────┤
│ Sidebar │ Main Column（max-width 720px，左对齐）    │
│ ~220px  │  ▾ 对话分组 A（3 条 · Sep 7）             │
│ All     │    ┌─ Note ────────────────┐             │
│ Sources │    └────────────────────────┘             │
│ 对话列表 │  ▾ 对话分组 B                             │
└─────────┴─────────────────────────────────────────┘
```

- **Sidebar 是过滤器不是管理器**：点击即过滤，消费已有数据，不引入新实体；可折叠，小窗口自动隐藏
- **Main Column 左对齐**：阅读动线从 sidebar 延续，消除当前全局居中造成的宽屏浪费
- **搜索 = 过滤即所见**：输入时 sidebar 计数同步变化，结果仍按对话分组；未来语义搜索替换的是匹配函数，不是交互

## 5. 交互清单（MVP 边界）

| 交互 | 行为 |
|---|---|
| Hover 卡片 | 浮出 Copy / Open Source / Markdown / Delete |
| 点击长笔记 | 展开/收起全文 |
| 点击组头 | 整组折叠/展开 |
| 点击 sidebar 项 | 过滤 + URL hash 同步（`#source=ChatGPT`），刷新不丢状态 |
| Esc | 清空搜索 / 关闭 Settings |
| 空状态 | 保留现有教学 + Open ChatGPT |

**明确不做**（等使用数据）：拖拽排序、手动置顶、卡片内编辑、多选批量操作。

## 6. 设计 Token

```css
/* 字体层级 */
--font-content: 16px / 1.7     /* 正文，唯一主角 */
--font-meta: 13px, muted       /* 上下文信息 */

/* 表面 */
--surface-card / --surface-group / --surface-sidebar
--border-subtle                /* 分隔靠留白 + 细分隔线，不靠重边框 */

/* 形状 */
--radius-card: 12px

/* 强调 */
--accent                       /* 唯一强调色，仅用于交互反馈（hover / 激活过滤项）*/

/* 布局 */
--sidebar-w: 220px
--column-w: 720px
组间距 32px / 卡片间距 12px
```

深色模式只换 token 值，不动结构。

## 7. 未来扩展落点（不可违反的约束）

| 未来能力 | 落点 |
|---|---|
| Tags（Layer 2） | 卡片 meta 行右侧 + sidebar 新一节 |
| Collections | sidebar 手动区域，与自动派生的 Sources / 对话并列 |
| Ask My Notes（Layer 3） | Topbar 搜索框升级 Search / Ask 切换，主列变回答视图 |
| 深色模式 | 仅替换 token 值 |
| 桌面 Agent 来源 | sidebar Sources 自动多一项，分组逻辑不变 |
