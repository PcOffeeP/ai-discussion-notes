# 部署与发布条件

本轮只修改工程与本地 Git，不调整线上服务，不申请付费资源，不推送触发发布。

## 同步存储

网关可通过 SYNC_STORAGE_FILE 指向外部持久化路径。Docker 提供 /data 挂载点，启动必须私密注入 SYNC_SECRET_TOKEN。服务重启使用同一文件维持 storageId，存储重建后客户端重新发送全量本地基线。每次确认响应均已完成临时文件写入、fsync 及原子替换；这不承诺在任何断电、磁盘损坏或文件系统情况下零损失，仍需备份。

现有 render.yaml 使用 free 计划，没有持久磁盘，适用于演示与短期测试。重部署等情况下文件可能丢失。选择生产托管前需要维护者确认持久卷方案、费用、备份和恢复策略；本轮不会自动更改付费计划。

## Android 签名

当前历史发布使用仓库中的 debug.keystore。保留它可以维持现有安装包的签名连续性，但公开的签名文件不构成私密发布身份，任何得到文件和密码的人都能签同一身份的包。不能通过改文件名或换 release 构建类型解决此问题。

迁移到私密签名会影响现有用户的覆盖安装。需要用户确认迁移方案，并由维护者私密保存新签名与配置 CI Secrets；本轮不会生成、替换或输出私密签名文件。是否增加可配置外部签名支持仍以用户确认的方案为准。

## 发版门槛

- 特性分支完整测试、版本与移动资产检查通过。
- 原生单元测试与 APK 构建在具备 JDK/SDK 的 CI 运行；设备集成测试单独验证。
- 本地 main 合并后，推送会触发 GitHub Release 与已连接的 Render 部署。推送前检查以上存储和签名条件。
